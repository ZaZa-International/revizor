# REVIZOR — Visual Research (Phase 1)

Дата: 17 ноября 2026. Цель: извлечь применимые принципы из профессиональных
референсов, не копируя их. Источники двух типов: **[F]** — первоисточник,
запрошенный и прочитанный в ходе аудита (URL ниже); **[K]** — устоявшиеся
публичные принципы продуктов/дизайн-систем, сформулированные по знаниям
модели (без попиксельного копирования; проверить по официальным гайдлайнам
перед заимствованием конкретики).

## 1. Промышленные GIS / infrastructure-продукты [K]

### Bentley iTwin / Hexagon HxDR / Siemens Xcelerator
- Реальные 3D-данные и фотографии — главный визуальный материал; интерфейс
  служит данным, а не наоборот. Панели инструментов компактны, тёмные,
  с высокой плотностью; цветовое кодирование несёт семантику (статус,
  классификация), а не decoration.
- **Применение**: showcase должен показывать реальные материалы продукта
  (кадры, карта, UI), а не рисунки «про» продукт. В Command Center цвет
  только семантический (band/severity/status) — уже соблюдается, сохранить.

### ArcGIS Utility Network / Experience Builder / Mapbox Studio / CARTO
- Карта — холст, UI — тонкие плавающие панели с чёткой иерархией: слои →
  фильтры → легенда → инспекция. Легенда компактная, с образцами геометрии
  (точка/кольцо/линия), а не только цвета.
- Mapbox Studio: тёмный редактор стиля, моноширинные координаты, минимальный
  хром вокруг карты. CARTO: аналитические виджеты поверх карты, каждый
  отвечает на один вопрос.
- **Применение**: MapPage уже трёхколоночный (слои | карта | инспекция) —
  сохранить. Легенду держать геометрическими образцами (уже так). Не
  добавлять панелей без задачи. Hover-обратная связь нужна для всех
  интерактивных слоёв, не только assets (VA-23) — принцип ArcGIS/Mapbox.

### Trimble Unity Field / Maintain
- Field-приложения: крупные тач-таргеты, статусы работ, фотофиксация как
  центральный объект. Maintain: реестры активов с историей обслуживания —
  прямой аналог Asset Passport.
- **Применение**: паспорт объекта — «история обслуживания» физической
  инфраструктуры; timeline истории и before/after наблюдений — ядро
  страницы (уже есть HistoryTimeline/ObservationCompare в inspection).
  В showcase история должна выглядеть как реальный timeline продукта.

## 2. Observability / data-интерфейсы [K]

### Grafana / Kibana
- Плотные дашборды: панели с заголовком-вопросом, единицы измерения всегда
  подписаны, нулевые/отсутствующие данные показываются явно («No data»),
  легенды и tooltip стандартизированы. Цвет = серия/порог, не украшение.
- **Применение**: каждый график Analytics уже имеет панель-заголовок и
  единицы; добавить явные empty-состояния (VA-02) и читаемые оси (VA-01).
  TimeHistogram с методологией («клиентская группировка ≤300 записей») —
  честный паттерн, сохранить.

### Linear / Vercel
- Эталон сдержанности: один акцент, тонкие границы, моноширинные числа,
  мгновенные состояния, клавиатурные ускорители, никаких декоративных
  градиентов в рабочем UI. Иерархия через типографику и плотность, не
  через рамки и тени.
- **Применение**: подтверждает текущий курс Revizor (плоские поверхности,
  один shadow-токен, mono-числа). Клавиатурные ускорители Reviews (1–4) —
  правильный паттерн; распространить keyboard-доступность на сортировку
  и вкладки (VA-08/09).

## 3. Дизайн-системы

### IBM Carbon [F]
- https://carbondesignsystem.com/building-blocks/data-visualization/overview
- https://carbondesignsystem.com/building-blocks/data-visualization/axes-and-labels
- Классификация: simple / flow / spatial charts. Для Revizor: bar/histogram
  (simple), pipeline (flow), карта/покрытие (spatial) — не смешивать типы
  без задачи.
- **Оси**: числовые оси bar-чартов ВСЕГДА от нуля (у нас так); не
  интерполировать пропуски данных; постоянные интервалы тиков; локальные
  форматы дат; «landmark»-подписи при смене цикла.
- **Применение**: ColumnChart переписать так, чтобы подписи были обычным
  текстом нормального кегля (сейчас ~6px и растянуты ×5.28 — VA-01),
  тики 0/50/100% пика сохранить, empty-ветка обязательна (VA-02).
  Carbon status-indicators: компактный маркер + текст, не иконка на каждый
  статус — совпадает с нашим Status/Badge.

### Microsoft Fluent 2 [F]
- https://fluent2.microsoft.design/iconography
- Иконки = семантические объекты; system icons в двух темах: regular
  (wayfinding) и filled (выделенное состояние). Размер по задаче: 12px —
  информация, интерактив — крупнее; на малых экранах крупнее тач-таргет.
- Цвет иконки: один цвет, контраст; не раскрашивать произвольно.
  Именование по форме/объекту, не по функции («shield», не «security»).
- **Применение**: наш набор — единый outline 1.6px, currentColor —
  соответствует regular-теме. Зафиксировать правило: filled-варианты не
  вводить без необходимости; доменные символы (колодец/опора/шкаф/кабель)
  держать в той же сетке 24 и толщине 1.6. Icon-only кнопки ≥32px таргет.

### Atlassian Design System [K]
- Icon usage: иконка сопровождает текст или заменяет его только при
  однозначной метафоре; декоративные иллюстрации — для empty states и
  onboarding, не для каждого действия. Illustrations: плоские, ограниченной
  палитры, объясняющие сценарий.
- **Применение**: EmptyState с одной иконкой Alert — допустимо; крупные
  иллюстрации в рабочих страницах не нужны. Pipeline-«картинки» showcase
  не соответствуют критерию «объясняет реальный процесс» — заменить
  реальными визуалами (VA-03).

## 4. UX-исследования

### NN/g — 10 эвристик [F]
- https://www.nngroup.com/articles/ten-usability-heuristics/
### NN/g — эвристики для сложных приложений [F]
- https://www.nngroup.com/articles/usability-heuristics-complex-applications/
- Ключевые подтверждения для Revizor:
  1. **Status**: при ожиданиях >10s generic-спиннер недостаточен — нужны
     шаги/прогресс (пример ArcMap). Наш stage-track JobDetail и polling-бейджи
     — правильное решение; Progress с процентами в Jobs — сохранить.
  2. **Real world**: доменная лексика (колодец, объезд, тяжесть S1–S5)
     вместо внутреннего жаргона; RU-справочники lib/labels.ts — верно.
  3. **Control**: отмена job должна быть безопасной (подтверждение — VA-11);
     append-only история = «restore previous version» паттерн Jitterbit.
  4. **Consistency**: один знак «+» = одно действие «создать» (Power BI).
     У нас IconPlus только для создания маршрута — верно; текстовые glyphs
     zoom/сортировки унифицировать (VA-24).
  5. **Error prevention**: превью результата до коммита (Salesforce) —
     у Reviews есть preview текста решения; CORRECTED-валидация — верно.
  6. **Recognition**: визуальные подсказки вместо запоминания (Revit hover
     preview) → hover-popup карты для всех слоёв (VA-23), кропы в очереди
     Reviews — уже верно.
  7. **Efficiency**: клавиши 1–4, Enter-строки, URL-состояние — верно;
     добавить keyboard-сортировку и arrow-tabs (VA-08/09).
  8. **Minimalism**: «gratuitous graphics» — иконки в однородных списках
     и декор без задачи вредят поиску. Прямое основание для удаления
     `.dots` (VA-28), мертвых иконок (VA-14) и переработки Pipeline-art.
  9. **Errors**: plain language + request_id + retry (наш ErrorState) —
     верно; ошибки Exports только toast — слабо (VA-25).
  10. **Help**: in-context подсказки (методология графиков, GPS-caveats,
     «не географическая карта») — уже сильная сторона, сохранить.

### WCAG 2.2 [K]
- Контраст текста 4.5:1 (крупный 3:1), нетекстовый контраст контролов 3:1
  (1.4.11), focus-visible (2.4.7/2.4.11), target size ≥24px (2.5.8),
  клавиатурная доступность всего функционала (2.1.1), отсутствие
  keyboard-ловушек, accessible names (4.1.2), status messages (4.1.3).
- **Применение**: DOM-аудит нашёл 1 нарушение контраста (segmented .on,
  3.47 — VA-07). Keyboard-пробелы: сортировка th, Tabs, подтаблицы паспорта
  (VA-08/09/22). Focus начальный в Dialog (VA-21). Toast — status message
  с aria-live уже есть; добавить dismiss (VA-10).

### web.dev — Core Web Vitals [F]
- https://web.dev/articles/vitals — LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 (p75).
- **Применение**: прошлый проход дал LCP 296–1124ms, CLS ≤0.023 — в норме.
  Новые ассеты не должны ломать бюджет: локальные webp с srcSet и LQIP,
  lazy-загрузка тяжёлых сцен (useNearViewport), preload ключевых шрифтов.
  INP: не добавлять тяжёлых синхронных обработчиков scroll; GSAP-scrub
  уже rAF-оптимизирован.

### Figma — design tokens [K]
- Токены — единственный источник решений; семантические слои (surface/ink/
  accent/status) поверх примитивов; изменения распространяются автоматически.
- **Применение**: литеральные дубли цветов в inline SVG (VA-19) нарушают
  принцип — перевести на CSS-переменные (inline SVG их поддерживает).

## 5. Award-галереи и «AI slop» [K]

Awwwards / CSS Design Awards / Webby / Mobbin / Refero / Godly / SaaSFrame /
Page Flows — наблюдение: отмеченные работы выделяются не количеством эффектов,
а (а) реальным контентом вместо стоковых заглушек, (б) одной сильной
композиционной идеей на секцию, (в) типографикой как носителем характера,
(г) осмысленным движением, привязанным к данным/состоянию.

Почему генеративные интерфейсы выглядят одинаково («AI slop»):
1. **Универсальные заполнения**: hero + 3 карточки + KPI с иконками +
   градиентный glow — паттерн, не привязанный к предметной области.
2. **Фиктивные данные**: красивые числа без источника; графики-декорации.
3. **SVG-иллюстрации «про» продукт** вместо самого продукта: условные
   прямоугольники с подписями monospace, одинаковые для любого SaaS.
4. **Одинаковая композиция каждой секции** без редакционной драматургии.
5. **Декоративные эффекты без функции**: blur/glow/тени на всём подряд.

**Критерий для каждого элемента Revizor** (применён в anti-slop-audit):
что обозначает → какую задачу решает → есть ли более достоверный способ →
нужно ли показывать → можно ли заменить реальным содержимым продукта.

## 6. Решения для Revizor (итог исследования)

1. **Showcase = продукт в действии.** Pipeline-стадии иллюстрируются
   реальными компонентами и данными (демо, маркировано): кадр+bbox,
   quality-метрики, dedup-координаты, факторы приоритета, review-кнопки,
   timeline. Разные форматы на стадию, не 8 одинаковых картинок.
2. **Command Center = плотность и точность.** Никакого промо-декора;
   графики с читаемыми осями и empty-состояниями; статусы компактные.
3. **Иконография**: единый outline-набор 24/1.6 (Fluent regular-подход),
   доменные символы в той же системе, никаких filled-миксов и мертвых иконок.
4. **Данные честные**: fallback-числа только из датасета; DEMO-маркировка;
   «—» вместо выдуманных нулей; подписи методологии.
5. **Движение служит состоянию**: scrub/reveal в showcase (обратимые, reduced-motion),
   в app — только функциональные переходы состояний.
6. **Доступность не приносится в жертву чистоте**: контраст ≥4.5, keyboard
   для всего интерактива, focus-управление в диалогах, dismissible toasts.
7. **Производительность**: локальные ассеты, LQIP, lazy-сцены, preload
   шрифтов; бюджет LCP/CLS удержать.
