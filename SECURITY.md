# Политика безопасности / Security Policy

MGTS Infrastructure Intelligence (backend `mgts-infra-backend`). Документ
описывает модель безопасности MVP и процесс сообщения об уязвимостях.
Архитектурное решение — [ADR-0012](docs/decisions/ADR-0012-security-model.md);
приватность данных — [docs/security/privacy.md](docs/security/privacy.md).

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 0.1.x (MVP) | Да: исправления безопасности выходят в рамках 0.1.x |
| < 0.1.0 | Нет |

## Модель безопасности (кратко)

- **Аутентификация**: логин по паролю (`POST /api/v1/auth/login`), пароли —
  **Argon2id**; выдаётся JWT **HS256** access-токен (TTL 60 мин по умолчанию,
  `exp`/`sub` обязательны, тип `access`, `jti`). Все эндпоинты, кроме
  `health`/`login`, требуют Bearer-токен; пользователь должен быть активен.
- **RBAC**: 4 роли — `ADMIN`, `OPERATOR`, `VIEWER`, `SERVICE`.
- **Секреты**: `JWT_SECRET_KEY` обязателен в production — без него приложение
  не стартует; фиксированных продакшен-секретов в коде нет. Bootstrap-админ
  создаётся только при пустой таблице пользователей и заданном
  `BOOTSTRAP_ADMIN_PASSWORD`.
- **Rate limiting**: логин — 10 попыток/мин на IP клиента; загрузка —
  30/мин на пользователя (Redis sliding window, 429 + `Retry-After`).
- **Загрузки**: лимит 2 ГиБ, санитизация имени, проверка расширения, MIME и
  **magic bytes** содержимого; несовпадение → 400.
- **Файлы**: анонимного доступа нет. S3 — presigned-ссылки с TTL (по умолчанию
  3600 с); local-бэкенд — аутентифицированный `GET /api/v1/files/{key}` с
  защитой от path traversal.
- **Логи**: редакция секретов (`password`, `token`, `authorization`, `secret`
  и т.п. → `[REDACTED]`); байты изображений и presigned-ссылки не логируются.
- **Аудит**: значимые действия (create/update/delete/review/login/export/
  job retry/cancel) пишутся в `audit_logs` с актором.
- **Зависимости**: `pip-audit` в CI в строгом режиме (любая известная
  уязвимость роняет сборку), еженедельный запуск по расписанию; pre-commit
  `detect-private-key`.
- **Приватность**: анонимизация лиц/номеров в MVP **не выполняется**
  (`NOT_APPLIED` честно во всех данных); доступ к кадрам ограничен ролями.
  См. [privacy.md](docs/security/privacy.md).

## Матрица ролей

| Возможность | ADMIN | OPERATOR | VIEWER | SERVICE |
|---|:---:|:---:|:---:|:---:|
| Чтение: активы, наблюдения, дефекты, карта, аналитика, задачи, маршруты | + | + | + | + |
| Просмотр файлов (`/files`, presigned) | + | + | + | + |
| Экспорты CSV/XLSX | + | + | + | + |
| ML health/model-info | + | + | + | + |
| Загрузка медиа, удаление загрузок | + | + | − | + |
| Создание/повтор/отмена задач обработки | + | + | − | + |
| Review наблюдений (confirm/reject/correct) | + | + | − | + |
| Редактирование активов (в т.ч. priority override с причиной), дефектов, маршрутов | + | + | − | + |
| Управление пользователями | зарезервировано (эндпоинтов в MVP нет) | − | − | − |

`SERVICE` — машинная роль для интеграций (например, автоматическая загрузка
съёмки); права на запись равны `OPERATOR`. Выделенных admin-эндпоинтов в MVP нет:
`ADMIN` фактически совпадает с `OPERATOR` по доступу и зарезервирован под
будущее управление пользователями.

## Обращение с секретами

- **`.env` никогда не коммитится** (`.gitignore`: `.env`, `.env.*`,
  исключение — `.env.example`). Шаблон — [.env.example](.env.example).
- `JWT_SECRET_KEY`: генерируйте `openssl rand -hex 32`; в production пустое
  значение = отказ старта. В dev допустим эфемерный случайный ключ.
- `BOOTSTRAP_ADMIN_PASSWORD`: задайте только на первый старт, затем смените
  пароль администратора и уберите переменную из окружения (рекомендация).
- `S3_ACCESS_KEY`/`S3_SECRET_KEY`: значения `minioadmin` в `.env.example` —
  dev-заглушки (историческое имя); в production используйте реальные ключи
  S3-сервера с аутентификацией и минимальными правами.
- Секреты не передаются в ML-запросах и не попадают в логи/экспорты.
- Доступ ML-сервиса к хранилищу — отдельные credentials только на чтение
  префикса загрузок; ML-сервис — в приватной сети, не публикуется наружу.

## Сообщение об уязвимости

**Пожалуйста, не создавайте публичные issue для уязвимостей.**

- Контакт: **security@mgts-infra.local** — ⚠️ **placeholder**: адрес-заглушка,
  замените на реальный приватный канал (почтовый ящик команды безопасности или
  private vulnerability reporting в GitHub) перед публикацией репозитория.
- Укажите: описание, шаги воспроизведения, затронутые версии/компоненты,
  оценку влияния, предлагаемое исправление (если есть).
- Ожидаемый процесс: подтверждение получения в течение 3 рабочих дней,
  триаж и оценка severity, исправление в поддерживаемой версии, согласованное
  раскрытие после выпуска фикса.
- Не включайте в отчёт реальные персональные данные и секреты; используйте
  синтетические примеры.

## Известные ограничения MVP (честно)

- Анонимизация ПДн на кадрах не выполняется (`NoopPrivacyFilter`,
  `NOT_APPLIED`) — до внедрения фильтра доступ к кадрам должен быть ограничен.
- Аутентификация backend ↔ ML отсутствует (доверенная приватная сеть).
- JWT — симметричный HS256; refresh-токенов и отзыва токенов (revocation) нет.
- Rate limiting при недоступности Redis переключается in-memory и не
  разделяется между репликами.
- Автоматических политик retention/удаления данных нет (рекомендации —
  [privacy.md](docs/security/privacy.md)).
- SeaweedFS в dev-конфигурации не проверяет S3-credentials; production-хранилище
  обязано быть с аутентификацией.
