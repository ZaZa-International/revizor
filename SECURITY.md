# Политика безопасности / Security Policy

MGTS Infrastructure Intelligence (backend `mgts-infra-backend`). Документ
описывает модель безопасности (MVP 0.1.0 + усиления 0.2.0) и процесс сообщения
об уязвимостях. Архитектурное решение —
[ADR-0012](docs/decisions/ADR-0012-security-model.md) (с поправками 0.2.0);
приватность данных — [docs/security/privacy.md](docs/security/privacy.md).

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 0.2.x (текущая разработка) | Да: исправления безопасности выходят в рамках 0.2.x |
| 0.1.x (MVP) | Да: критические исправления безопасности |
| < 0.1.0 | Нет |

## Модель безопасности (кратко)

- **Аутентификация**: логин по паролю (`POST /api/v1/auth/login`), пароли —
  **Argon2id**; выдаётся JWT **HS256** access-токен (TTL 60 мин по умолчанию,
  `exp`/`sub` обязательны, тип `access`, `jti`). Все эндпоинты, кроме
  `health`/`login`, требуют Bearer-токен; пользователь должен быть активен.
- **Logout и отзыв токенов (0.2.0)**: `POST /api/v1/auth/logout` помещает
  `jti` токена в **denylist в Redis** с TTL до `exp`; `get_current_user`
  проверяет denylist — отозванный токен больше не принимается. При
  недоступности Redis проверка denylist **fail-open** (осознанный компромисс:
  доступность важнее отзыва; окно риска ограничено TTL токена). Refresh-токенов
  по-прежнему нет.
- **RBAC**: 4 роли — `ADMIN`, `OPERATOR`, `VIEWER`, `SERVICE`.
- **Секреты (0.2.0, строгий production-валидатор)**: приложение не стартует в
  production при пустом/placeholder `JWT_SECRET_KEY` (`change-me*`, `changeme`,
  `secret`) или длине < 32 символов; при placeholder/коротком (< 12 символов)
  `BOOTSTRAP_ADMIN_PASSWORD` (пустое значение допустимо — bootstrap
  пропускается); при дефолтных S3-credentials `minioadmin`; при
  `QUEUE_MODE=inline`; при `'*'` в `CORS_ORIGINS` (в любом окружении).
  Фиксированных продакшен-секретов в коде нет; `.env.example` содержит пустые
  секреты. Bootstrap-админ создаётся только при пустой таблице пользователей
  и заданном `BOOTSTRAP_ADMIN_PASSWORD`.
- **Rate limiting**: логин — 10 попыток/мин на IP клиента **плюс 20/мин на
  username** (`RATE_LIMIT_LOGIN_PER_USERNAME_PER_MINUTE`, защита от перебора
  аккаунта с разных IP); загрузка — 30/мин на пользователя (Redis sliding
  window, 429 + `Retry-After`). При недоступности Redis — process-wide
  in-memory fallback (не разделяется между репликами). За reverse proxy
  настройте `FORWARDED_ALLOW_IPS`, иначе IP-лимит видит адрес proxy.
- **Лимиты тел запросов (0.2.0)**: ASGI-middleware ограничивает размер тела
  **до аутентификации**: multipart — `MAX_UPLOAD_SIZE_BYTES` (+ накладные
  расходы multipart), JSON — `MAX_JSON_BODY_BYTES` (2 MiB). Превышение → 413
  без полной буферизации (защита от unauthenticated disk/memory exhaustion).
  Edge-лимит reverse proxy (`client_max_body_size`) остаётся обязательным.
- **Security headers (0.2.0)**: `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'`; HSTS задаётся на
  TLS-proxy (см. deployment.md). CORS — только явные origin'ы, wildcard
  запрещён валидатором.
- **Загрузки**: лимит 2 ГиБ, санитизация имени, проверка расширения, MIME и
  **magic bytes** содержимого; несовпадение → 400. Удаление загрузки — только
  загрузивший пользователь или `ADMIN` (0.2.0). Дедупликация по SHA-256 между
  пользователями возвращает нейтральную запись без чужих метаданных/URL.
- **Файлы**: анонимного доступа нет. Медиа-URL (presigned, `image_url`,
  `crop_url`) и `GET /api/v1/files/{key}` — только `OPERATOR`/`ADMIN`/`SERVICE`;
  **VIEWER получает метаданные без медиа-URL** (кадры не анонимизированы).
  S3 — presigned-ссылки только GET с TTL (по умолчанию 3600 с) и публичным
  endpoint `S3_PUBLIC_ENDPOINT_URL`; local-бэкенд — аутентифицированная выдача
  с защитой от path traversal.
- **Логи**: редакция секретов (`password`, `token`, `authorization`, `secret`
  и т.п. → `[REDACTED]`); байты изображений и presigned-ссылки не логируются.
- **Аудит**: значимые действия (create/update/delete/review/login/logout/
  export/job retry/cancel) пишутся в `audit_logs` с актором.
- **Зависимости**: `pip-audit` в CI — job падает на любой известной
  уязвимости, еженедельный запуск по расписанию (план, волна 3: флаг
  `--strict` — падение и на непроаудированных зависимостях); pre-commit
  `detect-private-key`.
- **Приватность**: анонимизация лиц/номеров **не выполняется**
  (`NOT_APPLIED` честно во всех данных); доступ к медиа ограничен ролями
  (OPERATOR+, см. выше). См. [privacy.md](docs/security/privacy.md).

## Матрица ролей

| Возможность | ADMIN | OPERATOR | VIEWER | SERVICE |
|---|:---:|:---:|:---:|:---:|
| Чтение: активы, наблюдения, дефекты, карта, аналитика, задачи, маршруты (метаданные) | + | + | + | + |
| Просмотр медиа (`/files`, presigned/image/crop URL) | + | + | **−** (0.2.0) | + |
| Экспорты CSV/XLSX | + | + | + | + |
| ML health/model-info | + | + | + | + |
| Загрузка медиа | + | + | − | + |
| Удаление загрузок | любые | только свои (0.2.0) | − | только свои (0.2.0) |
| Создание/повтор/отмена задач обработки | + | + | − | + |
| Review наблюдений (confirm/reject/correct) | + | + | − | + |
| Редактирование активов (в т.ч. priority override с причиной), дефектов, маршрутов | + | + | − | + |
| Управление пользователями | зарезервировано (эндпоинтов нет) | − | − | − |

`SERVICE` — машинная роль для интеграций (например, автоматическая загрузка
съёмки); права на запись равны `OPERATOR`. Выделенных admin-эндпоинтов нет:
`ADMIN` отличается от `OPERATOR` правом удалять любые загрузки и зарезервирован
под будущее управление пользователями.

## Обращение с секретами

- **`.env` никогда не коммитится** (`.gitignore`: `.env`, `.env.*`,
  исключение — `.env.example`). Шаблон — [.env.example](.env.example)
  (секреты в шаблоне **пустые**, placeholder'ы запрещены).
- `JWT_SECRET_KEY`: генерируйте `openssl rand -hex 32`; в production пустое
  значение, placeholder или длина < 32 = отказ старта. В dev допустим
  эфемерный случайный ключ. **Несколько инстансов API** (реплики за
  балансировщиком) требуют явно заданного **общего** ключа: эфемерные ключи
  у процессов разные, и токены не будут проходить проверку между инстансами.
- `BOOTSTRAP_ADMIN_PASSWORD`: задайте только на первый старт (≥ 12 символов,
  не placeholder), затем смените пароль администратора и уберите переменную
  из окружения (рекомендация). Пустое значение = bootstrap пропускается.
- `S3_ACCESS_KEY`/`S3_SECRET_KEY`: значения `minioadmin` в `.env.example` —
  dev-заглушки (историческое имя), в production **отклоняются валидатором**;
  используйте реальные ключи S3-сервера с аутентификацией и минимальными правами.
- Секреты не передаются в ML-запросах и не попадают в логи/экспорты.
- Доступ ML-сервиса к хранилищу — отдельные credentials только на чтение
  префикса загрузок; ML-сервис — в приватной сети, не публикуется наружу.

## Сообщение об уязвимости

**Пожалуйста, не создавайте публичные issue для уязвимостей.**

- Контакт: **security@mgts-infra.local** — ⚠️ **placeholder**: адрес-заглушка,
  замените на реальный приватный канал (почтовый ящик команды безопасности или
  private vulnerability reporting в GitHub) перед публикацией репозитория.
- Укажите: описание, шаги воспроизведения, затронутые версии/компоненты,
  оценку влияния, предлагаемое исправление (если есть).
- Ожидаемый процесс: подтверждение получения в течение 3 рабочих дней,
  триаж и оценка severity, исправление в поддерживаемой версии, согласованное
  раскрытие после выпуска фикса.
- Не включайте в отчёт реальные персональные данные и секреты; используйте
  синтетические примеры.

## Известные ограничения (честно)

- Анонимизация ПДн на кадрах не выполняется (`NoopPrivacyFilter`,
  `NOT_APPLIED`) — доступ к медиа ограничен OPERATOR+ (0.2.0), но сам факт
  хранения неанонимизированных изображений сохраняется.
- Аутентификация backend ↔ ML отсутствует (доверенная приватная сеть).
- JWT — симметричный HS256; refresh-токенов нет. Отзыв (logout, denylist по
  `jti`) есть с 0.2.0, но при недоступности Redis проверка denylist
  **fail-open**: отозванный токен может приниматься до истечения `exp`.
- Rate limiting при недоступности Redis переключается in-memory и не
  разделяется между репликами.
- Автоматических политик retention/удаления данных нет (рекомендации —
  [privacy.md](docs/security/privacy.md)).
- SeaweedFS в dev-конфигурации не проверяет S3-credentials; production-хранилище
  обязано быть с аутентификацией.
- Базовый docker-compose пока публикует порты инфраструктуры на хост
  (dev-контракт); закрытие портов по умолчанию — волна 3 (SEC-4 аудита).
  До этого закрывайте 5432/6379/9000/9333 firewall'ом.
